# FIDO V3 — SystemVerilog kit (WITCHER / SV)

SystemVerilog version of the shared WITCHER code for **SYRAX** (P1, FIDO-X, compute side) and **CARAXES** (P2, FIDO-S, storage / sleep side).
It is the same design as the Verilog kit (`/home/testam/WITCHER`, `.v`), converted to SystemVerilog and **refactored into the RTL hierarchy of `FIDO_V3_RTL_Hierarchy_and_Formal.docx`**.
There is one module per file and one folder per block.

* **Language:** SystemVerilog IEEE 1800-2012 (`.sv`).
* **Target simulator:** Cadence Xcelium 22.09 (`xrun`).
* **Configurations:** the same 8 as the `.v` kit, with the same parameters, tests and report format:

  | Config | Technique | Policy |
  |---|---|---|
  | `cg_fine` / `cg_coarse` | CG | reactive |
  | `pg_fine` / `pg_coarse` | PG | reactive |
  | `cgpg_fine` / `cgpg_coarse` | CG + PG | reactive |
  | `cgpg_ml_fine` / `cgpg_ml_coarse` | CG + PG | ML (PG decisions) |

* **Two layouts:**
  * **Option A** (`optionA_self_contained/`): one design file plus one testbench file per configuration.
  * **Option B** (`optionB_common/`): the hierarchical source tree plus file lists.
  * Option A is *generated* from Option B, so the code is identical in both.
* **Shared code only.** The shared RTL covers both block sets: compute (SYRAX) and storage / sleep (CARAXES). The project innovations stay out of WITCHER, as agreed in README §11 of the Verilog kit:
  * SYRAX: look-ahead pre-wake, width gating.
  * CARAXES: RF-HI liveness, sleep escalation, inter-arrival features.

### Mapping from the Verilog kit

| `fido_common.v` / `tb_env.v` | SystemVerilog tree |
|---|---|
| `` `define FC_* / FU_* ``, maps, `dec()`, `immgen()` | `fido_pkg` (`ctl_t` packed struct, `decode()`, `immgen()`) |
| `icg_cell`, `pg_dff`, `pwr_switch_model`, inline `iso ? 0 : x` | `gating/` + `iso_clamp` (isolation cells as instances) |
| `policy_reactive`, `safety_shell` (FSM now a typed `enum`), generate blocks in `fido_top` | `pmu/` with `pm_domain`, `policy_ml_wrap`, `pm_sense`, `pmu_top` |
| `core_ctrl` (one 630-line module) | `if_stage`, `id_stage`, `regfile` + `rf_bank`, `hazard_unit`, `trap_unit`, `csr_unit`, `mem_stage`, `wb_stage`, `pipe_reg`, `rv32im_core` |
| `ex_stage` (one module) | `ex_stage` with `fwd_unit`, `alu_addsub`, `alu_logic`, `alu_shift`, `alu_cmp`, `mdu_ctrl` (+ unchanged `alu_hi_unit`, `mul_unit`, `div_unit`) |
| `rf_bank_hi`, RF-LO array in `core_ctrl` | one `rf_bank` module, two instances |
| `dmem_bank` x4 in `fido_top` | `dmem_banked` |
| `mcycle` / `minstret` in `fido_top` | `aon_counters` |
| `fido_tb_env` (one 1750-line module) | `fido_tb_env` + `fido_tb_programs`, `fido_tb_event_src` x2, `fido_tb_scoreboard`, `fido_tb_monitor`, `fido_tb_pkg` |

Every flop, clock net, power leaf, isolation point and reset value is unchanged, and so is the instruction set. The refactor only moves logic across module boundaries. Section 5 shows that it behaves cycle-identically.

SystemVerilog constructs used: packages, `logic`, `always_ff` / `always_comb` / `always_latch`, a typed `enum` FSM, the `ctl_t` packed struct, `int` / `string`, `automatic` tasks and functions, and `$sformatf`.
No classes, interfaces or assertions are used yet. SVA bind files and covergroups come next, on top of this tree.

## 3. Running on Xcelium 22.09

**Every new terminal: start Cadence first.**

```
cd /home/testam/WITCHER/SV
csh
source /home/install/cshrc        # prints "Welcome to Cadence tools Suite"
sh run_all.sh
```

| Command | What it runs |
|---|---|
| `./run_all.sh` | All 8 configurations, Option A. |
| `./run_all.sh -o B` | All 8 configurations, Option B (the source tree). |
| `./run_all.sh -k new -o B` | CG+PG and CG+PG+ML only. |
| `./run_xrun.sh -c cgpg_ml_fine -t 14 -w` | One configuration, test 14, SHM waveforms. |
| `./run_seeds.sh -c all -f 1 -l 20` | T11 random, seeds 1..20, every configuration. |
| `./run_ml_train.sh -i` | Trace runs, training, install into `ml_export/` and Option A. |
| `./run_icarus.sh -c all -o B` | Optional licence-free cross-check with Icarus 12 (`-g2012`). |

* The flags are the same as in the Verilog kit: `-c -k -o -t -s -w -g -v -n`.
* Every run makes a new folder in `SV/runs/`. The folder contents and the status rules are unchanged:
  * PASS: 0 warnings and 0 errors.
  * WARN: tests pass, Xcelium printed warnings.
  * FAIL: anything else.

**xrun options the scripts add:** `-sv -nowarn DSEMEL` plus a run-local `cds.lib` / `hdl.var`.
* `DSEMEL` is Xcelium's notice *"This SystemVerilog design will be simulated as per IEEE 1800-2009 SystemVerilog simulation semantics"*. It is printed for any SystemVerilog design and says nothing about this code.
* It is the only message the scripts suppress. Every other `*W` line is still counted and listed in `tool_warnings.txt`.
* The run-local `cds.lib` keeps out the known `*W,DLCPTH` from your `~/cds.lib` (`/home/testam/manish_ad`).

Raw commands, if you type them by hand (run-local cds.lib as in the `.v` kit):

```
# Option A
xrun -64bit -sv -nowarn DSEMEL -cdslib ./cds.lib -hdlvar ./hdl.var -top tb_cgpg_ml_fine \
     optionA_self_contained/design/fido_cgpg_ml_fine.sv optionA_self_contained/tb/tb_cgpg_ml_fine.sv
# Option B
cd optionB_common
xrun -64bit -sv -nowarn DSEMEL -cdslib ../cds.lib -hdlvar ../hdl.var -top tb_cgpg_ml_fine \
     -f flist/rtl.f rtl/cfg/fido_cgpg_ml_fine.sv -f flist/tb.f tb/tb_cgpg_ml_fine.sv
```

The file lists use `//` comment lines, which xrun accepts. Paths in them are relative to `optionB_common/`.

## 4. Testbench changes (behaviour of the checks is unchanged)

1. **End-of-test race removed.**
   * `wait_done` polled the scoreboard's `done` flag on the same negative edge where the scoreboard sets it.
   * Which process ran first decided whether one more edge was sampled, so `gated%` / `entries` could change by 1.
   * In SV the flag is polled on the positive edge, half a cycle later. Every simulator now gives Xcelium's numbers.
2. **Reset-assert race removed.**
   * `load_and_reset` dropped reset and the sampler enables on the same negative edge where the samplers read them. This only mattered after the T10 prelude: one ML-trace line of T10.
   * Reset is now asserted 1 ns after that edge, with no clock edge in between.
3. The ML trace writer now has its own cycle counter (same values as before).

## 6. ML models

* `rtl/ml_export/*.sv` hold the models now installed in your `.v` kit's `fido_common.v` (trained 10 Oct on Xcelium traces).
  * Note: the `.v` kit's `ml/ml_models.v` is older than the installed models (PD_STORAGE coefficients differ). The installed version was used here.

* `ml/install_models_sv.py` also accepts the Verilog kit's `ml_models.v` or `fido_common.v`.
